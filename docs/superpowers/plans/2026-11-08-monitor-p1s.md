# Monitor P1S Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Preheat & Resume with a Monitor P1S button that turns manual heating off when the print ends, using only `gcode_state`.

**Architecture:** The heat controller gains an *inhibit* (heater element off while heating stays enabled). The runtime exposes a fail-safe monitoring permit: while monitoring, the heater may run only while a ≤5 s permit is current. A pure `printer_monitor` state machine in `printer_control` turns printer state into permits and end decisions. The printer link is reduced to `gcode_state`, a merged report mailbox, a rate-limited `pushall`, and no time-server wait. Work is staged so every task ends with a green build: additive pieces first, then the control/API cutover, then removal of the old Resume/lease/link code.

**Tech Stack:** C (ESP-IDF v6.1, FreeRTOS, esp-mqtt, cJSON), host tests with MinGW + CMake/CTest, dashboard JS tested with `node:test`.

**Spec:** [docs/superpowers/specs/2026-11-07-monitor-p1s-design.md](../specs/2026-11-07-monitor-p1s-design.md)

## Global Constraints

- The only message the ESP32 publishes to the printer is the `pushall` status request. No Resume/Pause/Stop strings anywhere in `components/`.
- `pushall`: once after the first connection and after each reconnect while `gcode_state` is unknown; never more often than once every 5 minutes (300000 ms).
- Monitoring may only switch heating **off**, or let the owner's own heating come back after monitoring itself held it off.
- No print starts within 60 minutes (3600000 ms) of pressing → monitoring ends and heating is disabled.
- Belt and braces: while the print is PREPARE/RUNNING, no report at all for 5 minutes (300000 ms) → treat as lost connection.
- Permit length is at most 5000 ms; a missing renewal must hold the heater off within that time.
- Existing saved printer records (`printer_v1`) must still load (IP, serial, access code intact).
- Keep verifying the printer certificate against the bundled Bambu CA and the printer serial.
- Heater safety limits, sensor fault checks and fault latches are unchanged.
- Work on local `main`; commit after each task; never push. Do not flash the board, change printer settings or claim hardware behavior.

## Review Focus

1. **Leftover FINISH, then a new print:** press at FINISH, then FINISH → PREPARE → RUNNING → FINISH. Heating must stay on until the *final* FINISH. Pinned in Task 3 (`leftover_finish_then_new_print`) and Task 4 (`control_leftover_finish_sequence`).
2. **Print finishes while disconnected:** WATCHING, link drops, reconnect reports FINISH. Monitoring must end and disable heating. Pinned in Task 3 (`finish_seen_after_reconnect`).
3. **Unparseable report mid-print:** must not reconnect, must mark state unknown (heater held), and must make `pushall` due within the 5-minute limit. Pinned in Task 7 (`malformed_report_marks_unknown_without_reconnect`).
4. **Disable while held, then Enable again:** monitoring must end and the later Enable must heat normally, with no leftover inhibit. Pinned in Task 2 (`monitor_disable_then_enable`).
5. **Monitor task stalls:** permit not renewed → heater relay off within 5 s, heating still enabled. Pinned in Task 2 (`monitor_expired_permit_holds_heater`).

  ```c

    bool connected, state_known;

    uint32_t reconnects;

                 PRINTER_MONITOR_END_HEATING_OFF, PRINTER_MONITOR_END_SETTINGS } printer_monitor_end_t;
  typedef struct {
    printer_monitor_phase_t phase;
    printer_hold_t hold;

    uint64_t started_ms;
  ```

- Produces in `printer_monitor.h`:
  ```c
  #define PRINTER_MONITOR_WAIT_MS 3600000ULL
  #define PRINTER_MONITOR_SILENCE_MS 300000ULL
  #define PRINTER_MONITOR_PERMIT_MS 5000ULL
  void printer_monitor_init(printer_monitor_status_t *m);
  bool printer_monitor_start(printer_monitor_status_t *m, const printer_link_status_t *link, uint64_t now_ms);
  void printer_monitor_step(printer_monitor_status_t *m, const printer_link_status_t *link, uint64_t now_ms);
  void printer_monitor_stop(printer_monitor_status_t *m, printer_monitor_end_t reason);
  bool printer_monitor_heat_allowed(const printer_monitor_status_t *m);
  bool printer_monitor_end_disables_heating(printer_monitor_end_t reason);
  uint64_t printer_monitor_wait_remaining(const printer_monitor_status_t *m, uint64_t now_ms);
  ```
  Rules ("active" = PREPARING, RUNNING or PAUSED):
  - `start` returns false if phase ≠ OFF, `!connected` or `!state_known`. Otherwise `phase = active ? WATCHING : WAITING`, `hold = PAUSED` if paused else `NONE`, `started_ms = now`, `last_end = NONE`.
  - `step` when not OFF:
    - `!connected` → `hold = DISCONNECTED`.
    - else `!state_known` or `UNKNOWN` → `hold = UNKNOWN`.
    - else WATCHING and state PREPARING/RUNNING and `now - received_ms >= SILENCE` → `hold = DISCONNECTED`.
    - else active → `phase = WATCHING`, `hold = PAUSED` if paused else `NONE`.
    - else (IDLE, FINISHED, FAILED): if WATCHING → stop with `IDLE`/`FINISHED`/`FAILED`; if WAITING → `hold = NONE`.
    - Then, in any branch, if still WAITING and `now - started_ms >= WAIT` → stop with `NO_PRINT`.
  - `stop` sets `phase = OFF`, `hold = NONE`, `last_end = reason`.
  - `heat_allowed` = phase ≠ OFF && hold == NONE.
  - `end_disables_heating` is true for FINISHED, FAILED, IDLE, NO_PRINT and SETTINGS.
  - `wait_remaining` = WAIT − elapsed while WAITING, else 0.

  - `disconnect_holds_then_recovers`: WATCHING, `!connected` → hold DISCONNECTED; reconnect RUNNING → hold NONE.
